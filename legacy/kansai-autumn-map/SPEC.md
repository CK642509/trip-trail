# 關西賞楓地圖行程：產品規格（v2 交接）

狀態：原型已完成，準備交給 Claude Code 重新設計與正式部署。
最後更新：2026-11-20

---

## 1. 這是什麼

把一份 7 天 6 夜的關西家庭旅遊行程（2026/12/2–12/8）畫成互動地圖：每天去哪些景點、照什麼順序、搭什麼交通工具，一眼看清楚。

- **主要使用者**：出遊的爸媽（約 60 歲上下，用手機看，介面語言繁體中文）。
- **次要使用者**：規劃行程的子女（用電腦，會調整行程資料、分享連結）。
- **使用情境**：出發前一起看路線；旅途中在手機上查「今天下一站是哪裡、怎麼去」。

## 2. 原型現況（prototype/）

已發佈在 claude.ai 的單檔網頁 `prototype/index.html`，可直接用瀏覽器開啟。

| 項目 | 目前做法 |
|---|---|
| 地圖引擎 | Leaflet 1.9.4（cdnjs） |
| 底圖 | 沒有圖磚。內嵌 GeoJSON：府縣陸地（dataofjapan/land）、琵琶湖與鐵路線（Natural Earth 10m）、手畫鴨川 |
| 資料 | `prototype/data.js`，同內容的 JSON 版在 `data/itinerary.json` |
| 版面 | 桌機：左欄 360px 行程＋右側地圖；寬度 ≤ 760px：上地圖 55%、下行程 45% |
| 打包 | `scripts/build_prototype.py` 把 template、CSS、資料內嵌成單一 HTML |

為什麼沒有街道底圖：claude.ai 的網頁有內容安全政策（CSP），遠端圖片、Google Maps 腳本和 fetch 都會被擋。**正式部署後就沒有這個限制，v2 應換成真正的底圖。**

### 2.1 已實作的功能（v2 必須保留）

1. **顯示模式**：「一次一天」（像單選按鈕）或「多天同時」（像勾選框）；另有「顯示全部 7 天」按鈕。預設顯示全部 7 天。
2. **每天一個顏色**：7 種顏色，套用在路線、編號標記、行程欄。
3. **景點順序**：每個景點標示當天順序數字；路線上的箭頭指出前進方向（每約 190px 一個，短線段放中間）。
4. **相同地點合併**：同一天重複到訪的地點（例如京都站「1・10」），或多天共用的地點（例如「D1·2 D2·1·10 …」），合成一個標記。
5. **交通方式用線型區分**：鐵道為實線加白邊、巴士為粗虛線、遊覽船為圓點線、步行為細點線，交通方式未定的段落為淡色細虛線（只表示順序）。
6. **成群景點**：可以一起散步逛的景點用虛線圓圈起來並加上名稱；縮放等級 ≥ 11.5 才顯示。
7. **可選行程**：12/4 下午的伏見稻荷和宇治平等院是二選一，用空心虛框標記和較淡的虛線表示。
8. **多天重疊路線分開畫**：多天同時顯示時，各天路線依序左右偏移約 5px；同一天的來回路線也往行進方向的右側偏 3px，避免重疊。
9. **景點彈出視窗**：顯示 Day、順序、名稱、時間、備註，以及「在 Google 地圖開啟」連結（`https://www.google.com/maps/search/?api=1&query=lat,lng`）。
10. **行程欄**：依所選天數列出景點與主要交通（班次、時間）；點景點時地圖飛過去並打開彈出視窗；可用鍵盤操作（Enter／Space）。
11. **圖例**：說明線型、成群圈、可選行程與箭頭。
12. **單日連結**：網址帶 `#day-1` 到 `#day-7`，打開時直接進入該天的單日模式。

### 2.2 原型踩過的坑（v2 也要注意）

- 地圖必須先 `setView` 再加任何圖層，否則 Leaflet 的 `_clipPoints` 會報錯，整張地圖空白。
- 嵌在 iframe 裡時，容器剛載入可能沒有尺寸。要等容器有實際大小才初始化地圖，並用 `ResizeObserver` 監聽、尺寸改變時呼叫 `invalidateSize()` 再重畫。
- 箭頭、偏移線和成群圈都用像素座標計算，縮放後要重算（目前監聽 `zoomend viewreset`）。

## 3. 已知限制與問題（v2 要解決）

| # | 問題 | 建議方向 |
|---|---|---|
| 1 | 沒有街道和地名底圖，市區（例如 Day 2 東山）幾乎一片空白 | 換成真正的底圖：Google Maps JS API，或 MapLibre GL 加向量圖磚（MapTiler、Stadia、Protomaps 等） |
| 2 | 景點座標是憑記憶抓的大概位置，誤差可能達數百公尺；伊根、牧野、水杉大道、毘沙門堂最不確定 | 用 Google Places 或 OSM 逐一校正，並在資料裡記下 `placeId` |
| 3 | 鐵道路線是車站之間拉直線，不是實際軌道 | 用 OSM 鐵道或國土數值情報 N02 的線形，或 Google Directions（transit）取得的 polyline |
| 4 | 全覽縮放時，京都站的多天合併標記很寬，會蓋住附近景點 | 改成可展開的叢集標記，或縮小時只顯示色點 |
| 5 | 縮小時，同一區的景點編號互相重疊（例如天橋立站周邊） | 叢集或自動避讓標籤 |
| 6 | 只有淺色主題 | 加上深色模式（選用） |
| 7 | 手機版面沒有在實機測過 | 以手機為主重新設計，見 §5 |
| 8 | 資料寫死在 JS 裡，改行程要改程式 | 資料獨立成 JSON（`data/itinerary.json`），網站只讀資料 |
| 9 | 沒有離線能力，旅途中訊號差就無法使用 | PWA 加上離線快取（選用，見 §5） |

## 4. 資料模型（`data/itinerary.json`）

```jsonc
{
  "schemaVersion": 1,
  "trip": { "title": "...", "start": "2026-12-02", "end": "2026-12-08", "timezone": "Asia/Tokyo" },
  "modes": { "rail": {"label":"JR／鐵道","dash":null,"weight":5}, "bus": {...}, "boat": {...}, "walk": {...}, "open": {...} },
  "places": [ { "n": "京都", "ll": [35.0116, 135.7681], "lake"?: true, "sea"?: true } ],   // 底圖上的地名
  "days": [
    {
      "id": 1, "date": "12/2 (三)", "title": "抵達關西機場 → 京都", "color": "#2457c5",
      "stops": [
        { "id": "kix", "name": "關西機場", "ll": [34.4326, 135.2440],
          "time": "13:20–14:40", "note": "...", "optional"?: true }
      ],
      "legs": [
        { "from": "kix", "to": "kyo", "mode": "rail",
          "label": "HARUKA 32號 14:44 或 34號 15:14",
          "path": [[lat,lng], ...] | null,   // null = 兩個 stop 之間畫直線
          "optional"?: true }
      ],
      "groups": [ { "name": "清水寺～祇園 散步區", "stops": ["kiyo","san", "..."] } ]
    }
  ]
}
```

規則：
- 座標一律是 `[緯度, 經度]`（WGS84）。注意：GeoJSON 的順序相反。
- `stops` 的陣列順序就是當天的順序，編號從 1 開始。
- `stop.id` 只需要在同一天內唯一。同一地點可以出現多次（去程和回程各一次），用不同的 id。
- `legs.from` 和 `legs.to` 可以相同（例如伊根灣遊覽船繞一圈回到原碼頭）。
- `mode: "open"` 表示交通方式未定，只畫淡色虛線表示順序，不當成確定的交通路線。
- 目前共 7 天、45 個景點、40 段交通。

v2 建議擴充的欄位（待確認）：`placeId`（Google 或 OSM）、`address`、`openingHours`、`ticket`（例如「JR 關西廣域周遊券」）、`reservation`（指定席班次）、`legs[].duration`、`legs[].trainNo`。

## 5. v2 需求（請先跟使用者確認優先順序）

### 必要
- **R1 真實底圖**：看得到街道、車站、地名；中文地名優先。
- **R2 保留 §2.1 全部功能**，互動邏輯可以重新設計，但要做到同樣的事。
- **R3 手機優先**：在 375×667 的畫面上，不用橫向捲動就能看懂一天的行程；底部抽屜式行程欄，可以拖拉展開。
- **R4 正確的資料**：座標校正到誤差 50 公尺以內；行程內容以 `docs/itinerary.md` 為準。
- **R5 資料與程式分離**：改行程只需要改 JSON。
- **R6 部署成公開網址**：靜態網站即可，例如 GitHub Pages、Cloudflare Pages、Vercel。

### 加分
- **R7 「今天」模式**：依日本時間自動打開當天的行程，並標出下一站。
- **R8 一鍵導航**：每段交通都有「用 Google 地圖導航」連結（`https://www.google.com/maps/dir/?api=1&origin=…&destination=…&travelmode=transit`）。
- **R9 離線可用**：PWA，旅途中沒訊號也能看行程和已快取的地圖。
- **R10 實際軌道線形**：鐵道和巴士路線沿著真實路線畫。
- **R11 可列印**：列印或匯出成 PDF 時，每天一頁地圖加行程。

### 不做
- 帳號登入、多人即時共編、在網站上編輯行程（直接改 JSON 就好）。

## 6. 技術與部署建議（可調整）

- 前端：Vite + TypeScript，框架自選（React、Svelte 或不用框架）。
- 地圖二選一：
  - **Google Maps JavaScript API**：使用者已有 API key，地名和交通資料最完整。key 必須在 Google Cloud 主控台限制 HTTP referrer（只允許部署網域和 localhost），並限制可用的 API。
  - **MapLibre GL JS 加向量圖磚**：不綁 Google，可以完整自訂樣式，離線快取比較容易。
- **API key 不可提交到 git**：放在 `.env.local`，並加進 `.gitignore`。打包時注入的 key 一定會出現在前端，所以只能靠 referrer 限制保護。
- 資料校正腳本（選用）：讀 `itinerary.json`，用 Places API 查每個景點的 `placeId` 和正確座標，輸出差異報告讓人確認後才寫回。
- 自動化測試：用 Playwright 在桌機（1400×900）和手機（390×844）各截一張圖，作為版面回歸測試；另外檢查 console 沒有錯誤。

## 7. 驗收標準

1. 打開網址 3 秒內看到地圖和全部 7 天的路線，console 沒有錯誤。
2. 切換到任一天時，地圖自動縮放到那一天的範圍，路線、箭頭、編號和成群圈都正確。
3. 多天同時顯示時，各天顏色可以分辨，重疊路線看得出是不同天。
4. 手機（390×844）上，行程欄和地圖都能操作，文字不會被切掉。
5. 點行程欄的景點，地圖飛到該景點並顯示彈出視窗；彈出視窗裡的 Google 地圖連結可以正確開啟。
6. `#day-4` 這類連結可以直接打開指定的那一天。
7. 改 `itinerary.json` 裡任一景點的名稱或座標並重新部署後，網站跟著更新，不必改程式碼。
8. repo 裡找不到任何 API key。
